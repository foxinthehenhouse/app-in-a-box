# Teardown, 2026-10-01: does the kit meet the bar it borrowed?

**Scope:** the whole kit at v0.6.0 (plugin, template, selftest, CI, docs)
· **Method:** six fresh-context reviewers, each on one axis, every claim verified against the
file; the selftest run locally on a Mac; findings fixed in this PR or filed.

The kit packages the harness and production setup that grew up inside a shipped
strength-coaching app, with the app-specific parts removed. That app's team has one rule it
paid for repeatedly: **a guard that cannot fail reads as a guard that passes.** This teardown
asked, axis by axis, where the kit still breaks that rule.

## Verdict

Strong bones, blind edges. The architecture is right (agent-neutral `.agents/` source of
truth, generated adapters, git hooks as the hard layer, negative-controlled harness lint,
Postgres-backed state, strict JWKS auth, honest `/health`). What was wrong sat in the guards'
blind spots and in docs that described the previous release:

| Axis | Grade before | What was wrong | Status |
|---|---|---|---|
| Selftest portability | C | bare `python3` (3.9 on a Mac) failed 3 checks silently; BSD `od` spacing failed the icon check; `refuses` counted any non-zero exit as "guard fired" | fixed |
| CI / guards | B | PR-only template CI (no nightly, no main-red alert); `github.ref` concurrency groups drop main runs under a merge burst; ticket regex accepted `SHA-256` and dates; pre-commit missed `SUPABASE_SERVICE_ROLE_KEY=eyJ…`, the line provisioning writes | fixed |
| Harness mechanisms | B- | memory recall pointed at a directory that never exists; memory index loaded by instruction only; "merged branch is dead" was prose; hooks died silently when a worktree moved; no edit-time "ask" on migrations/CI/eas.json | fixed |
| Backend / DB | B+ | auth fallback sent an empty `apikey` under the recommended key setup (JWKS blip → mass sign-out); request models outside the wire-contract test; scoping scanner accepted any `user_id` filter; init rollback note would have broken sign-up | fixed |
| Mobile | B | `expo-dev-client` missing so the dev profile cannot build; contrast gate warn-only and kit-side; `screen_viewed` on mount under native tabs; paused offline mutation lost rollback + events; analytics opt-in never recorded; three guard scripts bypassable | fixed |
| Instructions | B | shape-first refactor never swept through (interview, design-directions, README, START_HERE); generated reviewer agents six lines long; TASTE.md never reached the generated repo; `$KIT` undefined in 8 skills; no never-list before hooks exist | fixed |
| Ecosystem / docs | B- | `userConfig.options` needed Claude Code ≥ 2.1.271 with no floor stated; three version identities; "every guard has a negative control" overstated; `<owner>` placeholders | fixed |

Decisions the owner took (⚖️ Kyle, 2026-10-02): Sonnet for the copywriter; React Compiler
on; `expo-secure-store` for the session; the kit has one home (this repo) and the copy inside
the originating monorepo was removed.

Left as tickets, with the reason: push-token hand-over threat model (owner decision), keep-alive
runs with the service key (consistent with the origin; narrow role is a follow-up), Codex-side
model tier map (opt-in design), Codex's newer plugin layout (keep the legacy layout until the
docs settle), the Supabase-only stack (dropped from v1 on purpose).

## Landed alongside, from the owner's other session

While this teardown was in flight, PRs #4 to #8 landed (routines as files, skill evals
passing, the production path, Maestro MCP and per-screen flows, component behaviour tests
and a coverage floor). Where they covered a finding here (eval graders, routines, gitleaks
plant) the teardown's own fix was dropped in favour of theirs; the merge resolved three
additive conflicts (the gates chain, build-feature's E2E step, the mobile AGENTS.md gate
list) as unions.

## What to copy back upstream

Six things the kit does better than the harness it came from: `tests/harness/` as the compiler
for prompts and configs; owner-asks as a lint; git hooks as the agent-neutral hard layer; the
AST scoping guard over every `.table()` chain; the no-in-process-state test; auto-discovered
wire pairs. They are listed here so the origin project can take them back.

## How to repeat this

Run six read-only reviewers in parallel, one per axis, each told to verify every claim by
reading the file and to list "checked, OK" so the next reviewer does not repeat it. Hand the
findings to fixers with disjoint file ownership, test-first. Finish with the selftest, not a
summary.
